# give-me-html — 直接产出精致的 HTML

产出物 = 一个自包含的 `.html` 文件。**内容的载体就是网页本身**，网页即文档。

输入两种情况，处理方式相同：

- 给了文档或素材 → 重构它的信息结构，不要照搬原文段落顺序
- 只给主题或口述需求 → 你就是内容作者，先组织信息结构再动笔

## 核心原则（违反任何一条即失败）

1. **禁止两道工序**：不许先写 Markdown 再转 HTML；不许把 md 源码、`#` 标题、`-` 列表直接塞进 `<p>` 或 `<pre>`。HTML 元素就是内容的表达方式本身。
2. **先设计后填写**：第一步规划信息架构（这份内容分几个模块、模块间什么关系），第二步选版式原型，第三步用组件填充。禁止从上到下 `<p>` 堆砌。
3. **单文件零依赖**：所有样式内联在 `<style>`；不引外部 CSS/JS/字体/图片（用户明确要求除外）；断网双击可打开。
4. **每个章节至少一个非文字模块**：通篇段落加 bullet 的章节，说明内容还没结构化完，回去拆成表格、卡片、步骤条或字段表。特别小的章节（一两句话的补充说明）可以用简略文字，不必硬凑模块。

## 第一步：选版式原型

根据内容类型选主版式（可混搭，但要有一个主原型）。**布局质量的源头在这里，选错原型后面无法补救**：

| 内容类型 | 原型 | 布局要点 |
| --- | --- | --- |
| 说明/需求/设计/规范/实现文档 | 阅读型 | 左侧固定锚点目录（≥3 个二级标题时必须）+ 右侧正文限宽 |
| 汇报/总结/方案宣讲 | 汇报卡片型 | 顶部概览条（关键结论或指标卡）+ 分区块卡片流，不做侧栏目录 |
| 流程/时序/步骤/操作指引 | 时间线型 | 垂直步骤条 + 阶段分组，每步一屏内说清 |
| 对比/选型/评审 | 对比型 | 双栏对照卡或对照表，差异点高亮 |
| 数据/统计 | 看板型 | 指标卡网格 + 表格或图示区（纯 CSS 图即可，不引图表库） |

## 第二步：内容用组件表达

| 内容 | 用什么 | 不允许 |
| --- | --- | --- |
| 章节标题 | 编号分节（01 / 02 …）+ 锚点 id | 裸 `h2` |
| 全文结论、一句话总纲 | 封面下的高亮摘要块 | 埋在第一段里 |
| 关键结论、指标 | 概览卡、指标卡（大号数字 + 标签 + 小字说明） | 埋在长段落里 |
| 并列要点、模块清单 | 要点卡网格 | 段落式"一是…二是…三是…" |
| 一组"标签 + 说明"的字段 | 字段表（左标签右内容的两列网格） | 段落里塞冒号 |
| 一个环节的完整说明 | 环节卡（带徽标的标题条 + 卡内字段表） | 一大段文字 |
| 条件 → 结果 的判断规则 | 斑马纹表格，第一列放主键 | "如果……那么……"的叙述 |
| 对比 | 双栏对照卡或对照表 | 文字描述对比 |
| 线性流程 | 流程链（节点 + 箭头，节点下可挂小字） | 大段文字 |
| 分步操作 | 步骤条、时间线 | 手写"1. 2. 3." |
| 补充说明、注意、风险、取舍 | 提示块（左侧色条 + 图标 + 标题），四种语义分开用 | 括号套括号 |
| 状态、分类 | 徽章 | 纯文本【标注】 |
| 可逐项验证的清单 | 带 checkbox 的验收清单 | 普通列表 |
| 文件路径、字段名、类名 | 行内 `code` 样式 | 加粗 |

组件用量也有节制：**同类模块不要连排超过三个**，连着五张字段卡和五段文字一样难读；提示块每章最多两个，满屏提示等于没有提示；表格不超过 5 列、单元格不超过 30 字，超了改用环节卡或卡片。

## 样式

字体、配色、圆角、间距这些自己定，按内容气质来，不必套模板。只守三条：

- **在 `:root` 里定成一套变量再用**，全局统一，不要每处硬编码。
- **正文限宽**，不通栏铺满；表格、图示、卡片网格可以占满容器。
- **面向中文排版**：中文字体优先，行高比英文文档松一些，标点和数字不要挤在一起。

深色是加分项，做就用变量做一套，可以跟随系统，也可以给个手动切换。

## 长文档的导航（≥3 个二级标题就必须有）

- 编号分节，每节一个 id 锚点，标题旁可放一个淡的 `#` 链接
- 宽屏左侧固定目录，窄屏折叠成 `<details>`
- 目录随滚动高亮当前章节，顶部一条 2px 阅读进度条——十几行内联脚本就够（监听 `scroll`，比较各节 `getBoundingClientRect().top`）
- 宽表格套一层横向滚动容器，避免整页横滚

## 图表

全部用 CSS 表达，不引任何图表库或渲染脚本：线性流程用流程链，分步用步骤条，对比用双栏卡，简单占比用纯 CSS 条形。状态机、时序、多分支这类复杂结构，用判定表或分组卡片表达，同样不上 mermaid 之类的渲染库。

## 精细度 checklist（交稿前逐项过）

- [ ] 版式原型选对了：文档给了目录，汇报给了概览条，流程给了步骤条
- [ ] 每章至少一个非文字模块，没有大片灰字墙
- [ ] 正文限宽，不通栏铺满
- [ ] 表格能一眼扫读：表头和正文分得开，第一列是主键
- [ ] 目录锚点可点、可回顶，滚动时高亮当前章节
- [ ] ≥375px 宽无横向滚动（宽表格套横滚容器）
- [ ] `<html lang="zh-CN">`，`<title>` 是内容名不是 "Document"
- [ ] 没有引任何外部 CSS/JS/字体，断网双击能打开

## 输出

写入一个 `.html` 文件（路径按用户上下文），完成后告知文件位置。
