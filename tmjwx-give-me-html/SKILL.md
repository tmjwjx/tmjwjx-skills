# HTML 文档交付

## 交付目标

- 产物是一个可直接打开的 `.html` 文件，信息清楚、排版完整，适合中文阅读。
- 基于素材制作时，保留事实、关键细节和来源，按阅读需要重组信息；已有 Markdown 可以作为输入，不将其源码直接堆进页面。
- 从主题创作时，区分已有事实与待确认内容，不为填充版式编造数据。
- 默认单文件、零外部依赖：CSS、必要的 JavaScript、SVG 及所需图片均内嵌，不加载远程字体、样式、脚本或图片。用户另有要求时遵循其要求。

## 内容与版式

- 文档以阅读为主，正文限宽；汇报突出结论和指标；操作指南突出步骤；比较内容突出差异。
- 并列信息用卡片，规则和对比用表格，顺序关系用步骤或流程，解释性内容用自然段。组件服务于理解，不为每章强行增加卡片或图表。
- 不机械限制组件数量、表格列数和字数；避免重复卡片、过密表格和无意义装饰。
- 长文档按导航需要提供锚点目录；阅读型可用侧栏，汇报型可用顶部导航，短页面不强制目录。窄屏导航折叠或顺排。
- 内容重组和视觉排版不得省略理解结论所需的依据与限制。

## 视觉与交互

- 使用一套 CSS 变量统一颜色、字号、间距和圆角，中文字体与行高适合连续阅读。
- 图示可使用 CSS 或内联 SVG；复杂关系保留节点、方向、条件和图例，不为零依赖牺牲表达。
- 表格和代码块可局部横向滚动，页面本身适配窄屏。
- 保留语义化标题、可辨识的链接、键盘焦点和足够的文字对比度。正文在 JavaScript 不可用时仍可阅读。
- 页面使用有意义的标题及与正文一致的语言标记。深色模式、阅读进度和滚动高亮按需提供。

## 检查与输出

- 检查事实与原始材料一致，目录、链接和交互有效，无意外外部资源依赖。
- 有浏览器预览能力时，检查桌面和窄屏布局、溢出及控制台错误；无法预览时明确说明，不将源码检查表述为视觉验证通过。
- 按用户指定位置保存；未指定时遵循当前工作环境的输出约定，交付可直接打开的文件。
